# Component acceptance contracts

Current review: 2026-10-08. All 55 designs have framework-native sources and complete distribution closures. All 165 sources remain **provisional** while full acceptance is incomplete. Local browser testing is now authorized and has been executed in Chromium, Firefox, and WebKit. Current results supersede earlier blocked-browser notes; see [the readiness report](readiness-remediation-2026-10-08.md).

For each source, verify declared input changes, event payloads, composition, keyboard focus and keys, accessible labels, state transitions, theme isolation, reduced motion, pause/replay, unmount cleanup, and recovery. `component-contracts.spec.ts` checks native default behavior, settled themes, inner/outer viewport bounds, accessibility, reduced motion, and simulated document visibility changes independently of `visual-regressions.spec.ts`. Visibility simulation tests lifecycle logic; it does not prove every physical-device background-tab behavior.

`integration.spec.ts` exercises application data, controlled values, complete event payloads, render functions/slots/snippets, empty states, unmount/remount, form semantics, and rejected-save recovery in all three frameworks. The four application-ready API additions are documented in compatibility guidance and authoritative manifests. Other designs still need custom-input/consumer acceptance where applicable; passing defaults or compilation does not automatically earn verified status.

Non-applicable capabilities must have a reason: a decorative field has no keyboard action; a source without declared callbacks emits no public event; a source without children/slots has no composition contract. Pure visuals without an async/error path do not need an artificial recovery control. Pointer effects must preserve readable content without a pointer. Host preview loading, retry, and clipboard recovery remain applicable independently.
