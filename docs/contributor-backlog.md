# Focused contributor work

Choose one reproducible task. Maintainers should check for an existing issue before opening a duplicate and attach scope-appropriate acceptance evidence.

| Suggested issue                                                | Suggested labels                | Acceptance                                                                                                                                       |
| -------------------------------------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Add a customized pagination integration recipe                 | good first issue, documentation | Show controlled page changes with real records; verify React, Vue, and Svelte snippets against the live examples.                                |
| Document one source installation in an existing Svelte project | good first issue, documentation | Record actual CLI output paths and `$lib` mapping; retain CSS/helpers/notices and show a working import.                                         |
| Add custom-input acceptance for one provisional design         | testing, framework-parity       | Define its manifest promise, test changed values and callback payloads in all declared frameworks, and preserve keyboard/reduced motion.         |
| Review keyboard access at 200% browser zoom                    | accessibility                   | Provide reproducible routes and viewports; check visible focus, dialog recovery, and horizontally scrolling content.                             |
| Measure on physical mobile devices                             | performance                     | Record device/browser/network, repeat representative routes, distinguish lab readings from field metrics, and attach actual evidence.            |
| Submit a real project to the showcase                          | showcase                        | Provide a public URL, component IDs/framework, creator permission, and a verifiable description. Do not invent adoption numbers or testimonials. |

Public issue templates already cover bugs, documentation, component submissions, and requests. This local backlog prepares concrete tasks without posting unreviewed issues to GitHub.
